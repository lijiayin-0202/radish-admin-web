# 04｜测试与验收规范（Web）

> 归属总纲：[AGENT.MD](../AGENT.MD)
> 硬要求：**测试流必须执行一轮且 4 个环节全绿**：**一轮测试 = 4 个环节**（本地构建 → Apipost 接口核对 → 浏览器页面 → 回归）；**执行一轮、项目可正常启动、页面链路跑通无报错即可判定「验证成功」**；多轮回归由开发者按需自测，**不再强制、不作 PR 阻断条件**。

---

## 1. 测试模型：一轮包含 4 个环节

| 环节 | 名称 | 目标 | 通过标准 | 失败动作 |
|------|------|------|----------|----------|
| 环节 1 | 本地验证 | 代码可构建、规范干净、页面能跑 | `npx eslint .` / `npm run build` / `npm run dev` 全通过 | 回到编码，修完重跑环节 1 |
| 环节 2 | 接口核对（Apipost） | 前端调用的接口与后端契约一致 | 全部接口返回 `code===0`，字段与页面字段一一对应 | 修复后**从环节 1 重跑** |
| 环节 3 | 浏览器页面验证 | 真实浏览器可用无报错 | Console 无 Error、Network 无 4xx/5xx、功能闭环 | 修复后回到环节 1 |
| 环节 4 | 回归测试 | 不影响既有功能 | 核心页面与登录/菜单/权限/字典全部正常 | 修复后重跑环节 1~3 |

**轮次要求**：测试流**执行一轮**即可（一轮 = 完整走完 4 个环节；轮内任一环节失败，修复后从环节 1 重跑本轮）；**不再强制 3 轮回归复测**，开发者可按需自行多轮验证，**多轮不作 PR 阻断条件**。

---

## 2. 环节 1：本地验证（本地必须成功）

```bash
npm install          # 依赖安装（锁文件一致）
npx eslint .         # ESLint 无 error（仓库无 lint 脚本）
npm run build        # 生产构建成功（必须）
npm run dev          # 本地启动（8080），首屏正常
```

必查项：
- [ ] 新增页面能正常打开，无编译报错、无 `console.log` 残留。
- [ ] 接口统一走 `utils/request`，url 不带 `/api` 前缀，无硬编码地址、无重复 axios 实例。
- [ ] 分页/查询/表单字段与后端契约一致（`page/pageSize/total/list`）。
- [ ] 枚举、字典与后端一致，无前端自造状态值。
- [ ] 无新增无关依赖；`package.json` 与锁文件同步提交。
- [ ] 构建产物体积无明显异常增长。

---

## 3. 环节 2：Apipost 接口核对（接口必须全绿）

> 前端同样需要用 Apipost 验证接口，确保页面字段与真实响应一致。

**用例设计（每个接口至少 4 类）**

| 类别 | 示例 |
|------|------|
| 正常 | 必填齐全 → `code===0`，字段齐全 |
| 边界 | 分页 `page=0/超大`、空查询、超长输入、空列表 |
| 异常 | 缺必填、非法枚举、ID 不存在、token 失效 |
| 权限 | 无权限账号访问受限接口（应被拦截） |

**执行要求**
1. 在 Apipost 建/更新模块接口集合，环境变量区分本地/联调/测试。
2. 每个接口执行 ≥3 次（首次 + 修复后 + 数据变化后），结果**截图存档**。
3. 逐字段比对：接口响应字段 ↔ 页面表格列/表单字段，缺字段、命名不一致（驼峰 vs 下划线）必须记录并修复。
4. 写接口验证数据库/列表刷新结果；列表接口验证 `total` 与分页一致性。
5. 失败记录：请求报文、响应报文、页面表现、Console 输出 → 缺陷单闭环。

**接口核对记录模板**

| 接口 | 场景 | 入参 | 期望 | 实际 | 执行结果 | 状态 |
|------|------|------|------|------|----------|------|
| GET /cs/ticketList（baseURL `/api`） | 正常分页 | page=1&pageSize=10 | code=0、list/total | | ✅ | 通过 |

---

## 4. 环节 3：浏览器页面验证（浏览器不能报错）

1. 用浏览器打开页面，**F12 Console 无 Error**（允许无害 warning，需说明）。
2. **Network 面板**：无 404/500 请求，无重复无效请求，接口响应 `code===0`。
3. 功能闭环：列表加载 → 条件查询 → 新增 → 详情 → 编辑 → 删除 → 列表刷新一致；分页切换、每页条数切换正常。
4. 状态：空数据、加载中、请求失败、无权限均正常展示，无白屏。
5. 表单：必填校验提示与后端一致；重复提交被禁用；成功后弹窗关闭并刷新列表。
6. 异常操作：连续点击、快速翻页、并发提交不产生脏数据。
7. 分辨率：1280×720 与 1920×1080 下布局不破版（表格横向滚动正常）。
8. 截图存档：列表页、表单页、详情页各一张 + Console 面板 + Network 面板各一张。

---

## 5. 环节 4：回归与专项

- 核心链路回归：登录 → 菜单加载 → 目标模块 → 关联模块（工单 ↔ 会话 ↔ FAQ）。
- 全局回归：布局、主题、语言切换、退出登录、路由跳转、面包屑。
- 权限回归：不同角色账号看到的菜单/按钮正确，越权访问被拦截。
- 性能（按需）：首屏加载时间、大数据量列表渲染、导出/导入耗时。
- 异步链路（Kafka 相关）：提交异步任务后状态可刷新，最终一致结果正确展示。

---

## 6. 判定标准（DoD）

只有同时满足以下条件，才可对外宣称"验证成功"：

- [ ] 环节 1 本地：`npx eslint .` / `npm run build` / `npm run dev` 全通过
- [ ] 环节 2 接口：Apipost 全部用例 ≥3 次执行通过，字段与页面一致，截图齐全
- [ ] 环节 3 页面：浏览器 Console/Network 无报错，功能闭环，多分辨率正常，截图齐全
- [ ] 环节 4 回归：核心链路与全局功能无回归
- [ ] 测试流已执行一轮：4 个环节全绿、项目可正常启动、页面链路无报错（多轮回归按需自测，非阻断）
- [ ] 缺陷全部闭环（有编号、有复现、有修复 commit）
- [ ] 菜单/权限配置说明已同步（如涉及新页面）

---

## 7. 测试红线

1. 禁止"不跑测试流/只看页面能打开"就判定通过（一轮内 4 个环节必须完整走完）。
2. 禁止用生产数据/生产环境调试；测试数据需脱敏。
3. 截图禁止包含手机号、token、密钥等敏感信息。
4. 测试不通过的代码禁止提交 PR、禁止合入 `main`。
5. 测试记录与截图必须随 PR 提交，缺失视为未自测。
6. 后端接口未就绪时，禁止伪造数据"让页面看起来正常"后宣称完成。
